# 調査スクリプト

特定の疑問を確かめるために書いたもの。**常設の検査ではない。**

常設の検査は以下を使うこと。

| コマンド | 内容 |
|---|---|
| `npm run audit` | 総合監査（収支4種 + 停止検出 + 数値解法 + 軌跡統計、64x32 で 6分） |
| `npm test` | 95 個の物理テスト |
| `npm run smoke` | ブラウザでの通し確認 |
| `npm run gpu-verify` | GPU 版と CPU 版の数値一致（要 `npm run dev`） |

## ★ 全史ランは並列で回すこと

このマシンは 24 論理コア（Ryzen 9 7900X）・62GB。
Node は 1 プロセス 1 スレッドなので、条件ごとにプロセスを分ける。
**実測: 10 本並列で壁時計 411 秒（1 本単独 340 秒）= スループット 8.3 倍。**

```bash
for c in 0 1 2 3; do
  npx vite-node scripts/probes/probe-shatter.ts --width 64 --case $c > /tmp/sh-$c.log 2>&1 &
done
wait
grep -h RESULT /tmp/sh-*.log
```

全史 1 本の目安: 64x32 で約 6 分、96x48 で 12 分、128x64 で 35 分、160x80 で 60 分。

## いま現役のもの（2026-08-27 の M4.7 段階1 調査で作った）

| スクリプト | 何を測るか |
|---|---|
| `probe-landmetric.ts` | 「陸のまとまり具合」の指標が**解像度独立か**を選別する。初期地形は解像度が違っても同じ惑星になるので試験台に使える。**ばらつきではなく傾きで判定すること** |
| `probe-landmass.ts` | `public/timelapse.*` から陸のまとまりを測る（陸地面積 / 最大陸塊の占有率 / **有効陸塊数** / 0.1%以上の陸塊の数）。`npm run audit -- --timelapse` の後に回す |
| `probe-shatter.ts` | 大陸を砕いている機構の総当たり。`--case N`（機構を止める）/ `--plates N` / `--foreland 0\|1` |
| `probe-collapse.ts` | 冥王代の地形崩壊を機構別に追う。体積の収支と**厚さ分散の台帳**を並べて出す |
| `probe-peak.ts` | 300Myr で山が育つか。`--corr 0\|1\|2` で移流の体積補正の方式を切り替えて比較 |
| `probe-accretion.ts` | `accretionBonus` × 結合間隔 の A/B。**数字には必ず条件を添えること**の教訓の元になった |
| `probe-lip.ts` | LIP テストの検出力。seed 内では 5/8 のコイン投げ、seed 間なら r=0.610 |

### 指標について（2026-08-27 に決めた）

**主指標は有効陸塊数（逆シンプソン）`(Σa)² / Σa²`。**
「実質いくつの大陸か」を表し、塵のような島は a² が効かないのでほぼ数えない。

| | 地球 | 初期地形 | 現状(64x32) |
|---|---|---|---|
| 有効陸塊数 | **2.56** | 3.02 | 8.06 |

**陸塊の「数」と海岸線の長さは使わないこと。** セル数にほぼ完全比例する
（傾き +40.9% と +14.2% / 解像度2倍）。`probe-landmetric.ts` で選別済み。

> 陸塊の数が 217 → 31 に減ったのを改善と読んで半日溶かした。
> 陸が 12.7% → 3.0% に消えていただけだった。**母数を先に確認すること。**
