# ドット絵の指示書

Gaia Protocol に差し込む**アイコン**の仕様書。外部（ChatGPT など）に
発注するときは、この文書のリンク先ではなく**この文書そのものを渡す**こと。

## 0. 何を作るのか / 作らないのか

**作るもの: アイコン。** タイムラインに刻まれる出来事、テクトニクスの様式、
生命の能力、UI の記号。**1 概念 1 ファイル**の透過 PNG。

**作らないもの: 地形タイル・惑星の絵。**
惑星の表面（海・陸・氷・溶岩・植生）は `src/render/layers/natural.ts` が
標高・氷率・陸率・生物量から**毎フレーム手続き的に着色**している。
タイルを貼る構造ではないので、地形の絵は使い道が無い。

## 1. 共通仕様

| | |
|---|---|
| 形式 | PNG・**透過**（背景は完全な透明。白で塗らない） |
| 大きさ | **64×64 px**（UI の記号だけ 32×32 も可） |
| ドットの粒 | 1px = 1 ドット。**縮小前提の高解像度で描かない** |
| 色数 | 1 枚あたり **6 色以内**（下のパレットから選ぶ） |
| 輪郭 | **暗い輪郭を付ける**（`#1A1614`）。背景が明暗どちらでも読めるように |
| 光の向き | **左上から**。ハイライトは左上、影は右下 |
| アンチエイリアス | **使わない**。半透明ピクセルは輪郭の外側 1px までに留める |
| 向き | 生物・道具は**左向き**に統一 |

★**32px の中に収める**こと。64×64 の外周 16px は余白として空ける
（タイムライン上で密に並ぶので、詰まると読めない）。

## 7.5 ★ 出来事のポップアップ絵（128×128・アニメーション）

**シムアース的な「いま何が起きたか」のポップアップ**に出す絵。
§3 の 64×64 アイコンとは**別物**で、同じ主題の「大きい・動く版」。

### 形式

| | |
|---|---|
| 1 フレーム | **128×128 px**（透過 PNG） |
| フレーム数 | **4** または **6**（多いほど良いが、全点で揃える方が優先） |
| 納品形 | **横一列に並べたストリップ 1 枚**（4 コマなら 512×128、6 コマなら 768×128） |
| GIF でも可 | GIF で出た場合はこちらでコマに分解する。**その場合もコマ数を明記** |
| 再生 | **ループ**。8 fps（1 コマ 125ms）を想定 |
| パレット | §2 と同じ。1 枚あたり 8 色まで（動きの分だけ増やしてよい） |
| 余白 | 外周 8px は空ける（アイコンほど厳しくしなくてよい） |

★**動くのは 1 要素だけにする。** 背景と地形は**全コマまったく同じピクセル**にして、
噴煙・波・氷・泡だけがコマごとに変わる。全部動かすとドット絵は破綻する。

★**コマ間で線がずれないこと。** 同じ絵を複製してから差分だけ描き替えると揃う。

| ファイル名 | 出来事 | 何が動くか |

| `anim-lip.png` | 巨大火成岩岩石区の噴出 | **溶岩の噴出が伸び上がり、噴煙が広がる**。地面は固定 |
| `anim-impact.png` | 隕石衝突 | 1: 空の火球 → 2: 着弾の閃光 → 3: 噴き上がる土 → 4: 広がるダスト |
| `anim-tsunami.png` | 海進（津波） | 波が**左から右へ寄せて**岩を飲む。引き波で戻る |

| `anim-icehouse.png` | 氷期に入った | 白い氷が**縁から中心へ伸びる**（4 コマで覆う） |
| `anim-greenhouse.png` | 氷期が明けた | 氷に亀裂 → 割れる → 水が覗く → 滴が落ちる |

ポップアップにも流用する（拡大表示）。

### こちら側の実装（**実装済み** 2026-09-01）

- 出す側（`src/sim/*.ts`）が `WorldEvent.code` に絵の名前を入れる。
  ★**本文の日本語で絵を選ばない。** 文言を直した瞬間に絵が消えるため
- 表示は `src/ui/eventPopup.ts`。`ANIM` の表で
  「出来事の絵 → 動く絵」を引く。**名前から機械的に導かない**
  （`ev-transgression` の動く版は `anim-tsunami`、起源の 3 箇所は
  1 本の `anim-origin` を共有する）
- 再生は CSS のみ（`.epop-strip` の `steps(4)`）。
  **コマ数を変えたら `steps(4)` と一緒に直すこと**
- **ファイルが無ければ静止アイコン、それも無ければ文字だけ**に落ちる。
  だから 1 枚できた時点から差し込める（全部揃うまで待つ必要はない）
- `prefers-reduced-motion` の人には 1 コマ目で止める

## 7.6 ★ 生命体の絵（64×64・8 枚 + 色替え）

### なぜ「種ごとに 1 枚」にできないか

このシムの生命は**種の一覧を持っていない**。クレードは
**16 の連続形質 + 9 の能力ビット + 体制 7 軸**（`bodyPlan.ts`）で表され、
組み合わせは開かれている
（`docs/02` §1.6「教科書にするか、開かれた進化にするか」）。

なので **「段階（グレード）ごとに 1 枚」+ 「クレードごとに色を替える」** にする。
8 枚で 16 クレードすべてに顔がつく。

### 段階の判定（上から順に最初に当たったもの）

| # | ファイル名 | 条件 | 絵の内容 |
|---|---|---|---|
| 1 | `life-symbolic.png` | 象徴 **かつ 脳 ≥ 0.3** | 道具か記号を持つ生き物。**顔があってよい唯一の段階** |
| 2 | `life-land.png` | 陸への耐性 + 多細胞 | 陸に乗り上げた多細胞。四肢または匍匐 |
| 3 | `life-predator.png` | 骨格 + 捕食 | 殻または骨を持つ捕食者。口と眼 |
| 4 | `life-multicellular.png` | 多細胞 | 軟体の多細胞。群体か扁形 |
| 5 | `life-eukaryote.png` | 真核 | 核とミトコンドリアが見える単細胞 |
| 6 | `life-cyanobacteria.png` | 酸素発生型光合成 | マット状（ストロマトライト）。酸素の泡 |
| 7 | `life-swimmer.png` | 運動性 | 鞭毛のある原核 |
| 8 | `life-prokaryote.png` | それ以外 | 桿菌・球菌の集まり。**LUCA はこれ** |

★**この順序は「進化の梯子」ではない**（§2.1「はしごを廃止する」）。
1 枚を選ぶための優先順位でしかなく、段階を飛ばす惑星も戻る惑星もある。

### ★色替えのキー色

**体の主要部分を `#FF00FF`（マゼンタ）で塗ってください。**
エンジンがここを**クレードごとの色**に置き換える（`cladeColor(id)`）。
同じ段階でも系統ごとに違う色になり、地図の優占クレードの色と一致する。

- 影とハイライトは、マゼンタを**暗くした/明るくした色**で塗る
  （`#AA00AA` と `#FF88FF`）。エンジンが同じ比率で置き換える
- 眼・口・骨・道具など**色を変えたくない部分**は、パレットの他の色を使う
- 背景は透過

★**象徴だけは能力ビットに加えて脳の形質も見る**（`CLAUDE.md` の 50）。
ビット 1 つで名乗らせると、獲得後は無償で子孫に広がって
**16 系統中 10 系統が知性種**になった（実測）。

### 実装（2026-09-05）

- 段階の判定: `src/ui/creatureGrade.ts` の `gradeOf()`
- 色替えと絵の読み込み: `src/render/creatures.ts`
- 地図への配置: `planetView.ts` の `drawCreatures()`

★**マゼンタの判定は完全一致にしていない。** ドット絵は手で塗るので
1 だけずれた画素が必ず出る。完全一致にすると**マゼンタの点が取り残される**。
「赤と青が揃っていて緑が弱い」を条件にしている。

★**地図では間引いて置く。** 全マスに同じ絵が整然と並ぶと「壁紙」に見えて
地図が読めなくなる（罠 32: 表示は可視化であって転写ではない）。
セルが `MIN_CELL_PX × 2.4` より大きくなったら密に置く。

★**1 ドットの影を敷いてから本体を描く。** 生き物は地図と同じ系統色に
塗ってあるので、そのままだと**同じ色のセルに沈んで見えない**（実測）。

### 使う場所

| どこ | どう出るか |
|---|---|
| 虫眼鏡（マスをクリック） | そのマスに同居しているクレードごとに 1 枚ずつ |
| 出来事のポップアップ | 分岐・絶滅・上陸のとき |
| 地図（拡大時） | 1 セルが十分大きいときだけ、優占クレードの絵を置く |

**絵が無い段階は能力アイコン（§6）にフォールバック**するので、
1 枚できた時点から差し込める。

## 7.7 ★ 集落の絵（64×64・6 枚 + 色替え）

### なぜ「文明ごとに 1 枚」にできないか

★**この順序は進歩の梯子ではない**（§2.1）。1 枚を選ぶための優先順位でしかなく、
段を飛ばす文明も、失伝して戻る文明もある。

★**時代名（`eraOf`）とは別の関数にしてある。** 時代名は 3 軸
（素材・社会・エネルギー）で読ませるが、絵は 1 枚しか置けないので
**1 本に潰す**必要がある。潰し方を共有すると片方を直したとき壊れる。

### 色替えのキー色（§7.6 と同じ）

建物の主要部分を `#FF00FF`、影を `#AA00AA`、ハイライトを `#FF88FF`。
★**煙・窓の灯り・畑・炎は塗り替えない**（パレットの他の色にする）ので、
文明の色が変わっても**煙は煙の色のまま**である。

### 実装

- 段階の判定: `src/ui/settlementGrade.ts` の `settlementOf()`
- 色替えと読み込み: `src/render/settlements.ts`
- 地図への配置: `planetView.ts` の `drawSettlements()`
- 文明タブの一覧: `src/ui/civPanel.ts`

★**生き物と違って間引かない。** 文明の領域は 1 惑星で数十セルしかなく、
**都市がある場所そのものが情報**なので、間引くと
「どこに人が住んでいるか」が嘘になる（罠 82）。

★**生き物より少し小さく（0.62 × セル）、少し下に置く。**
生き物の上に重ねるので、同じ大きさだと生き物が完全に隠れる。

### いまの素材は生成物である

`scripts/art/towns.py` が ASCII の絵柄から PNG を書いている。
**どの画素がマゼンタ（色替えの対象）かが読んで分かる**ことを優先した。
★**手で描いた `.aseprite` に差し替えてよい** —— ファイル名と
マゼンタの約束さえ守れば、コードは何も変えなくてよい。
