# 05. ロードマップ

## 3つのフェーズ

| フェーズ | 内容 | マイルストーン |
|---|---|---|
| **1. 物理的な惑星** | 地質・地表・大気が、科学的な計算式に基づいて一つの系として回る。**生命なし** | M0 – M4 |
| **2. 生きた惑星** | 生命が環境を変え、環境が生命を選別する | M5 |
| **3. ゲーム** | 文明、介入、勝敗、メタ進行 | M6 – M7 |

**フェーズ1 が本作の土台であり、最も時間をかけるべきところ。**
ここで「地球が回っているだけで面白い」状態を作れなければ、上に何を積んでも救われない。
フェーズ1 の終わりに一度立ち止まり、**生命抜きで 45 億年を眺めて面白いか**を評価すること。

計算資源の話（CPU / GPU、グリッド解像度）は [04-architecture.md §8](04-architecture.md) に分離した。
**要点だけ: フェーズ1 は CPU（512×256）で完結させ、GPU 移植はフェーズ2 で行う。**
ただし移植可能な形で書くための規則（§8.5）は**初日から守る**こと。

## 原則

各マイルストーンは **「動く惑星」を1段階豊かにする縦割り** で切る。「気候モデルを全部作ってから描画」のような横割りにはしない。
そして各マイルストーンには **合格条件（検証テスト）** を置く。テストが通らないうちは次に進まない。シミュレーションゲームは、下層が間違っていると上層で必ず破綻する。

- ✅ 全球平均降水 989 mm/yr（現実 ~1000）、陸 723（現実 ~750）
- ✅ 造山で侵食が増え、供給律速の面積が減る（サーモスタットが強まる）
- ✅ 氷河侵食が有意に効く（氷期の総侵食への寄与 +86%）
- ✅ 樹枝状の河川網ができる（最大河川の集水域が陸地の 2.1%、地球のアマゾンは 4%）

**M3 で判明したこと**

1. **`docs/01-6.6c` の「気候 → 侵食 → サーモスタット自己修復」は符号が逆だった。** ★
   供給（侵食）の温度感度は **3.7 %/K**、需要（風化）は **7.6 %/K**。
   需要が 2 倍速く増えるので、**暑い惑星ほどサーモスタットが弱い**。
   これは温暖化への正のフィードバックであり、当初書いた負のループではない。
   §4.2 で 🟡 として挙げた「熱力学的制約下で風化が正のフィードバックに反転する」
   （Maher & Chamberlain、Winnick & Maher）と同じ機構を独立に再現したことになる。
2. **造山は逆向きに効く。** 同じ +18% の侵食増でも、気候経由は 29.2→30.7%（悪化）、
   造山は 29.2→28.7%（改善）。造山は供給だけを増やすので符号が正しい向きになる。
   **プレイヤーの「造山を促す」介入は「惑星を冷やす」介入と質的に違う。**
3. **M2 の CO₂ 応答が飽和するようになった。** 侵食の空間分布が 587 倍に広がるため、
   高侵食の「エンジン」領域が全球の風化を担い続ける（§4.2）。
4. **窪地埋めには微小勾配が必須。** 等高で埋めると平坦域ができて D8 が流下先を
   見つけられず、河川網ができない。
5. **降水の温度依存を線形にしてはいけない。** `(1 + 0.07(T−15))` は T ≈ 0.2℃ で
   負になり、氷期に降水がゼロになる。降水はエネルギー律速で 2〜3 %/K なので
   `exp(ΔT/35)` を使う。0.07/K は水蒸気量の値であって降水の値ではない。

- ✅ **大陸地殻の体積が保存される**（体積比 0.96〜1.03、解像度非依存）
- ✅ 海嶺が浅く古い海盆が深い（`depth = 2600 + 350√age`。実際の海底で <20Myr −2969m vs >80Myr −4499m）

- ✅ 暴走温室（460℃・水の喪失）でプレートが停止し、**ヒステリシスで再開しにくい**
- ✅ **脱氷で火山活動が 34.7 倍**（アイスランドの実測 30〜50 倍と一致）
- ✅ 深部水循環が数十億年スケールで緩やかに動く

**M4 で判明したこと**

1. **スケールの導出を怠ると 11 桁間違える。** ★
   造山速度を最初 `9e10` と置いていたが、物理から導くと `≈6`。
   （収束 5cm/yr が幅 300km の帯を 50Myr で 35→70km に厚くする = 7e−7 km/yr、
   境界の発散は v/(2·セル幅) ≈ 1.2e−7 /yr、よって比は約 6）
   誤った値では地殻が 1 ステップで上限に張り付き、大陸面積が 15〜45% で暴れた。
   **境界での発散という「単位が直感的でない量」に係数を掛けるときは、必ず観測量から逆算すること。**
2. **セミラグランジュのバイリニア移流で大陸が消えた。** ★
   1 ステップの変位が 0.16 セルでも、400 ステップ積むと数値拡散が拡散長 5 セル分たまり、
   大陸縁が海に溶けて陸地面積が 26% → 3.6% まで落ちた。
   プレートは剛体回転するので、**累積回転が 1 セルに達したときだけ最近傍で再サンプル**すれば
   数値拡散はゼロになる。地質時間スケールでは 1 セル単位の移動でも十分なめらか。
3. **最近傍の回転再サンプルは緯度経度格子で面積保存にならない。**
   再サンプルのたびに 1 セル規模の取りこぼしが出て、再サンプル頻度の高い高解像度ほど
   損失が積もる（128×64 で 176Myr に体積 0.74）。移流の前後で総体積を保存させる。
4. **島弧の成長を「セルあたりの厚さ増加率」で書くと解像度依存になる。**
   弧の幅は有限差分の性質上つねに約 2 セルなので、絶対的な弧の面積が解像度に反比例する。
   64×32 で +26%、96×48 で ±0% と食い違った。
   **総体積の増加率（地球は 1〜2 km³/yr）を目標に置き、弧の総面積で割って配分する。**
5. **侵食を地形に接続しないと大陸が「厚く狭く」なり続ける。** ★
   衝突で地殻が山に集中する一方、削られないため陸地面積が 29% → 17% と減り続けた。
   M3 の侵食場で削剥し、削れた分を**浅い海（大陸棚）に堆積**させると 21% で安定する。
   これで M3 ↔ M4 のループが閉じた。
6. **準静的なサブシステムに小さい `preferredStepYears` を与えてはいけない。**
   水循環に 100 年を与えていたため `SimLoop` の刻み全体を支配し、
   40 Myr の要求が 0.8 Myr しか進まなくなった。D8 のソートと窪地埋めも毎サブステップ走っていた。

### ★45 億年の全史ランで閉じた収支（当てずっぽうをやめて測った話）

M4 の合格条件（21/21）を満たした時点でも、45 億年通すと大陸が消えた。
**パラメータを当てずっぽうで動かして 5 回外した**あと、方針を変えて
**地殻の厚さにも寄与台帳を付けて測った**（docs/04-5 の考え方を地殻に適用）。
そこで一発で犯人が分かった。

**400 Myr の体積収支 [10⁹ km³]:**

| プロセス | 測定前の想定 | 実測 |
|---|---|---|
| 侵食 + 堆積 | ← ここを疑って 5 回いじった | **−0.0000（無実）** |
| **リフティング** | — | **−0.59** ← 最大の漏れ |
| **体積クランプ** | — | **−0.21** |
| 造山 | | +0.88（移動量。体積中立） |
| 島弧の付加 | | +0.56 |

**判明した 4 つの構造的な誤り:**

1. **リフティングが地殻を薄くするだけで、物質の行き先が無かった。**
   実際の伸張は「薄くなる代わりに広がる」ので体積保存。隣接セルに配る。
2. **体積クランプが「閾値以上の体積」で判定して全セルに作用していた。**
   移流で地殻が閾値をまたぐだけで発火し、実体積を削っていた。保存量は総体積の方。
3. **弱い発散でも一律にリフティングしていた。**
   大陸地殻が外向きに広く拡散し、陸の閾値の直下に溜まった。
   実際の大陸分裂は持続的な強い伸張を要する（閾値を設ける）。
4. **侵食の平衡点が「海面ちょうど」だった。** ★これが本丸
   削るのは標高 > 0 のセル、堆積先は浅い海。系全体が海面高度に引き寄せられ、
   10 億年で 36% のセルが陸の閾値の直下に溜まって陸地が 4.6% になった。
   実際の準平原は標高が下がると侵食が事実上止まる（楯状地は 0.001〜0.005 mm/yr）。
   **侵食が止まる標高（0.25km）を設けて平衡点を持ち上げる。**

**結果（45 億年、64×32）:**

| | 修正前 | 修正後 |
|---|---|---|
| 陸地面積（最終） | 0.1% | **35.1%**（29% で開始、振動しながら持続） |
| 大陸地殻の体積 | 0.65 | **1.20**（緩やかに成長して飽和） |
| LIP | 13 回 | **20 回**（地球は 20〜30 回） |
| クランプ発生 | 0 回 | 0 回（数値的に安定） |

陸地面積は超大陸サイクルに合わせて振動する（集合すると造山で面積が減り、
分裂すると棚ができて増える）。振幅は実際の地球より大きい（0.3〜35%）が、
これは造山の強さの調整の問題であって構造的な欠陥ではない。

> **教訓: 保存則を持つ量が合わないときは、パラメータを動かす前に収支を測る。**
> 5 回の手戻りのうち 4 回は、測っていれば避けられた。
> このプロジェクトは寄与台帳を最初から入れる方針だったのに、
> 地殻の厚さにだけ台帳を付けていなかった。

> ### ★ここがフェーズ1の完成点
>
> **地質・地表・大気が、科学的な計算式に基づいて、生命抜きで一つの系として回る。**
> 大陸が動き、山ができ、雨が降り、川が削り、サーモスタットが効いたり壊れたりする。
> 45 億年を眺めて面白いかどうかが、ここで決まる。
>
> **面白くなければ、上に生命と文明を積んでも救われない。** ここで一度立ち止まって評価すること。

## M4.5 — 気候ソルバの GPU 移植（WebGPU）✅

**受け入れ基準と結果:**

| 基準 | 結果 |
|---|---|
| WebGPU が無い環境で従来どおり動く | ✅ `World.climateBackend` が null なら CPU 版。94 テスト無影響 |
| CPU 版と数値が一致する | ✅ 最大セル差 0.0006 K（256×128 冷スタート、f32 の丸めの範囲） |
| ゲーム設定で実用精度 | ✅ 256×128 温スタートで 0.12 K（CPU 対話設定は 0.10 K） |
| 1 solve につき読み戻し 1 回 | ✅ PCG のスカラーも GPU 上に置いた |
| 決定論的なリダクション | ✅ 集計は固定小数点 atomics、CG 内積は順序固定 f32 二段 |
| ブラウザで実際に動く | ✅ smoke テストで `solve … · GPU`、平均 14.49℃（CPU 14.50℃） |

**測れなかったこと（正直に）:** 実 GPU の速度。WSL に `dzn` Vulkan ICD が無く、
Chromium は SwiftShader に落ちる。**正しさは検証できたが速度は検証できていない。**
実測は Windows 側のブラウザで行う必要がある。詳細は `docs/04-8.4b`。

**この段階で学んだこと:**

1. **WebGPU はエラーをその場で投げない。** バインド数の上限超過（既定 8 本）で
   `createBindGroupLayout` が失敗しても例外は出ず、以降が静かにゼロを返すだけになる。
   `device.onuncapturederror` を最初に張ること。
2. **固定小数点リダクションは万能ではない。** 大きさが有界な集計には向くが、
   CG の内積のように 4〜6 桁変動する量では有効数字が消える。
   順序を固定した f32 の二段リダクションなら atomics 無しで同じ決定論性が得られる。
3. **同じ「良い擬似時間刻み」が、CG の停止条件によって得にも損にもなる。**
   固定反復（GPU）では大きな刻みが有利、許容誤差まで回す（CPU）では不利。
   仮説を立てて測り、否定できた。

**増加分は科学的な現代化のコストである。** 内訳のほとんどは、1990 年的な単純モデル（一本道のグレード、無条件のサーモスタット、常在するプレートテクトニクス、技術の階段）を、条件付き・確率的・可逆なモデルに置き換える作業。

## 途中で捨てる判断

- **M1 で正しい分岐が出ない場合** — EBM のパラメータ調整に時間を溶かさず、Budyko の原論文の値に戻して、まず現実の地球を再現することに専念する。ゲーム的な誇張は後で足す。
- **M5 のバイオマス更新が重すぎる場合** — クレード数上限を 30 に落とす。グリッドを 256×128 に落とす。**モデルを単純化するより解像度を落とす方が、面白さは失われにくい**
  （そもそも解像度は精度を買わない — `04-architecture.md` §8.2）。あるいは GPU 移植を前倒しする。
- **M4 のテクトニクス様式が破綻する場合** — 様式遷移をマントル熱史からの創発ではなく、**時刻でスクリプト**する（それでもシナリオ #3 は成立する）。創発は M8 に回す。
- **M6 の社会が破綻する場合** — 並立する社会を 1 つに固定する。ただし**生業ミックスと可逆な階層性は捨てない**。これは技術ツリーへの退行であり、§00-3 の表で「作り直す点」に挙げた核心だから。
